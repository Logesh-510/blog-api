# Blog Notification Center — React Frontend

A responsive **React + Vite frontend** for the **Blog Management API**.

This application provides an authenticated user interface for:

* 📊 User Dashboard
* 🔔 Notification Center
* 🤖 AI Support Chat
* 🔐 JWT Authentication
* 📈 Blog activity analytics
* 💬 Notification and support interactions

The frontend communicates with the FastAPI backend through REST APIs.

---

## 📌 Project Overview

The **Blog Notification Center** frontend is built using React and Vite and connects to the FastAPI Blog Management API.

After login, authenticated users can access their blog activity dashboard, notification center, and AI Support Chat.

The application provides:

* User authentication using JWT
* User-specific dashboard analytics
* Blog activity chart
* Post statistics
* Notification management
* Automatic notification refresh
* AI Support Chat with FAQ-based responses
* Responsive design for desktop, tablet, and mobile

## 🔄 Automatic Notification Refresh

The frontend automatically requests the latest notification information from the backend every **10 seconds**.

> **Note:** The application uses periodic polling every 10 seconds. It does not use WebSockets or instant push notifications.

Notification flow:

```text
User Login
    ↓
JWT Token Stored
    ↓
Fetch Notifications
    ↓
Display Notification Bell
    ↓
Show Unread Badge
    ↓
Check Backend Every 10 Seconds
    ↓
Update Notification List
```

## 🤖 AI Support API Integration

The frontend communicates with the following backend endpoints.

```http

```

  "message": "How do I create a post?"

# 🔐 Authentication Flow

The frontend uses the backend JWT authentication system.

## Login

The frontend sends the username and password to:

```http
POST /auth/login
```

After successful authentication:

1. The backend returns a JWT access token.
2. The token is stored in browser `localStorage`.
3. The frontend uses the token for authenticated API requests.
4. Dashboard data is loaded.
5. Notifications are loaded.
6. AI Support history is loaded.

Example authorization header:

```http
Authorization: Bearer <access_token>
```

For security, actual JWT tokens are not stored in the source code.
