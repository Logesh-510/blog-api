# Blog Notification Center — React Frontend

A responsive **React + Vite frontend** for the **Blog Management API**.

The application provides an authenticated user interface for:

* 📊 User Dashboard
* 🔔 Notification Center
* 🤖 AI Support Chat
* 🔐 Username/Password Authentication
* 🔑 Auth0 Social Authentication
* 🌐 Google Login
* 📘 Facebook Login
* 📈 Blog Activity Analytics
* 💬 Notification and Support Interactions

The frontend communicates with the FastAPI backend through REST APIs.

---

# 📌 Project Overview

The **Blog Notification Center** frontend is built using React and Vite and connects to the FastAPI Blog Management API.

After authentication, users can access:

* User dashboard
* Blog activity analytics
* Notification Center
* AI Support Chat
* User-specific post statistics

The application supports both:

* Traditional username/password authentication
* Auth0 social authentication using Google and Facebook

# ✨ Features

## 🔐 Authentication

The application supports two authentication methods.

### Username and Password

* Username/email and password login
* JWT-based authentication
* JWT access token stored in browser `localStorage`
* Bearer token authentication for protected API requests
* Automatic logout when the backend returns `401 Unauthorized`
* Logout button

### Auth0 Social Authentication

Auth0 is integrated for social login.

Supported providers:

* 🌐 Google
* 📘 Facebook

Auth0 handles the social authentication process and returns an ID token to the frontend.

The frontend then exchanges the Auth0 ID token with the FastAPI backend.

Authentication flow:

```text
User
  ↓
React Frontend
  ↓
Auth0
  ↓
Google / Facebook
  ↓
Auth0 ID Token
  ↓
FastAPI /auth/auth0-login
  ↓
Backend JWT
  ↓
localStorage
  ↓
Authenticated Application
```

The backend verifies:

* Auth0 token signature
* Auth0 issuer
* Auth0 audience
* Auth0 signing key
* Email availability
* Email verification status

If the Auth0 user does not already exist in the local database, a local user account is created automatically.

# 🔄 Automatic Notification Refresh

The frontend automatically requests the latest notification information from the backend every **10 seconds**.


# 🔐 Authentication Flow

## Traditional Login

The frontend sends the username and password to:

```http
POST /auth/login
```

After successful authentication:

1. The backend returns a JWT access token.
2. The token is stored in browser `localStorage`.
3. The frontend uses the token for protected API requests.
4. Dashboard data is loaded.
5. Notifications are loaded.
6. AI Support history is loaded.

Example authorization header:

```http
Authorization: Bearer <access_token>
```

---

## Auth0 Login

Google and Facebook authentication are handled through Auth0.

The frontend uses the Auth0 React SDK to initiate social authentication.

After successful authentication:

```text
Google / Facebook
        ↓
      Auth0
        ↓
   Auth0 ID Token
        ↓
React Frontend
        ↓
POST /auth/auth0-login
        ↓
FastAPI verifies ID Token
        ↓
Local user created/found
        ↓
Backend JWT generated
        ↓
JWT stored in localStorage
        ↓
Dashboard / Notifications / AI Support
```

Auth0 backend endpoint:

```http
POST /auth/auth0-login
```

The ID token is sent to the backend for verification.

The backend validates the token using Auth0's JWKS endpoint and verifies the expected:

* Audience
* Issuer
* Signing algorithm
* Signing key
* Email
* Email verification status

Actual tokens and credentials are not stored in the source code.

---

# 👤 Auth0 User Creation

When a user signs in through Google or Facebook for the first time:

1. Auth0 authenticates the user.
2. The frontend receives the Auth0 ID token.
3. The frontend sends the ID token to the FastAPI backend.
4. The backend verifies the token.
5. The backend checks whether the email already exists.
6. If the user does not exist, a local account is created.
7. A backend JWT is generated.
8. The frontend stores the backend JWT.
9. The user can access protected application features.

This allows Auth0 social users to work with the existing backend authorization system.
